# Go Pet Shop

Учебный REST API интернет-магазина товаров для питомцев. Проект написан на Go и использует PostgreSQL для хранения пользователей, товаров, заказов, позиций заказа и платежных транзакций.

Проект показывает развитие API от обычного CRUD до атомарного оформления заказа и аналитических запросов.

## Возможности

- создание и просмотр пользователей — с v1;
- CRUD для товаров — с v1;
- создание заказов и добавление позиций — с v2;
- атомарное оформление заказа и изменение остатков — с v3;
- история заказов по email пользователя — с v4;
- список популярных товаров — с v4;
- health-check приложения.

## Версии проекта

Каждая часть задания находится в отдельной ветке:

- **v1** — CRUD для товаров и пользователей. Формирует базовый каталог и учёт покупателей.
- **v2** — заказы и позиции заказа. Связывает пользователей с выбранными товарами.
- **v3** — транзакционное оформление заказа. Остатки, заказ, позиции и платёж сохраняются целиком либо откатываются при ошибке.
- **v4** — история заказов и популярные товары. Добавляет пользовательскую историю и бизнес-аналитику.

Ветки идут последовательно: `v1 → v2 → v3 → v4`.

## Быстрый запуск v4

Для запуска нужны Docker и Docker Compose.

1. Создайте локальный файл с переменными окружения:

```bash
cp .env.example .env
```

2. В ветке v4 поднимите весь проект одной командой:

```bash
docker compose up --build
```

Compose выполнит следующие действия:

1. запустит PostgreSQL;
2. дождётся готовности базы;
3. применит миграции;
4. запустит HTTP-сервер.

После запуска API доступно по адресу `http://localhost:8080`.

Проверка состояния:

```bash
curl http://localhost:8080/health
```

Остановить проект:

```bash
docker compose down
```

## Запуск v1–v3

В исторических ветках PostgreSQL запускается через Compose, а мигратор и приложение — с хоста:

```bash
docker compose up -d postgres
task migrate
go run cmd/app/main.go
```

## Запуск с чистой базой

Данные PostgreSQL хранятся в Docker volume. Чтобы удалить данные и проверить v4 на полностью чистой базе:

```bash
docker compose down -v
docker compose up --build
```

При новом запуске база создаётся с нуля, после чего мигратор применяет файлы из каталога `migrations`.

В v1–v3 после `docker compose down -v` повторите команды из раздела «Запуск v1–v3».

## Переменные окружения

Основные переменные перечислены в `.env.example`:

- `POSTGRES_USER` — пользователь PostgreSQL;
- `POSTGRES_PASSWORD` — пароль PostgreSQL;
- `POSTGRES_DB` — имя базы данных;
- `DB_HOST` — адрес базы при запуске команд с хоста;
- `DB_PORT` — порт PostgreSQL на хосте;
- `DATABASE_URL` — строка подключения к базе;
- `APP_ENV` — конфигурация приложения: `local` или `dev`; если переменная отсутствует, используется `local`;
- `DB_TIMEOUT` — тайм-аут подключения к базе; значение по умолчанию — `10s`.

В v4 приложение внутри Docker Compose подключается к PostgreSQL по имени сервиса `postgres`.

## Миграции

В v4 при обычном запуске через `docker compose up` миграции применяются автоматически.

Для ручного запуска миграций, в том числе в v1–v3:

```bash
docker compose up -d postgres
task migrate
```

Файлы миграций:

- `migrations/0001_create_tables.up.sql` — создание таблиц;
- `migrations/0001_create_tables.down.sql` — удаление таблиц.

## Основные HTTP-ручки

### Состояние приложения

- `GET /health` — с v1.

### Товары

- `GET /products` — список товаров, с v1;
- `GET /products/{id}` — товар по ID, с v1;
- `POST /products` — создание товара, с v1;
- `PUT /products/{id}` — обновление товара, с v1;
- `DELETE /products/{id}` — удаление товара, с v1;
- `GET /products/popular` — популярные товары, с v4.

Пример создания товара:

```bash
curl -X POST http://localhost:8080/products \
  -H "Content-Type: application/json" \
  -d '{"name":"Корм для собак","price":1200,"stock":10}'
```

### Пользователи

- `GET /users` — список пользователей, с v1;
- `GET /users/{email}` — пользователь по email, с v1;
- `POST /users` — создание пользователя, с v1;
- `GET /users/orders?email=user@example.com` — заказы пользователя, с v2;
- `GET /users/history?email=user@example.com` — история оформленных заказов, с v4.

Пример создания пользователя:

```bash
curl -X POST http://localhost:8080/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Иван","email":"ivan@example.com"}'
```

### Заказы

- `POST /orders` — создание заказа, с v2;
- `POST /orders/{id}/items` — добавление позиции, с v2;
- `GET /orders/{id}` — заказ с позициями, с v2;
- `POST /checkout` — атомарное оформление заказа, с v3.

Пример оформления заказа:

```bash
curl -X POST http://localhost:8080/checkout \
  -H "Content-Type: application/json" \
  -d '{
    "email":"ivan@example.com",
    "items":[
      {"product_id":1,"quantity":2}
    ]
  }'
```

При оформлении заказа в одной транзакции:

1. проверяются пользователь, товары и остатки;
2. уменьшаются остатки товаров;
3. создаётся заказ;
4. создаются позиции заказа;
5. записывается платёжная транзакция.

Если любой шаг завершается ошибкой, изменения откатываются.

## HTTP-статусы

- `200 OK` — успешное чтение или обновление;
- `201 Created` — успешное создание;
- `400 Bad Request` — неправильный JSON или некорректные входные данные;
- `404 Not Found` — пользователь, товар или заказ не найден;
- `500 Internal Server Error` — внутренняя ошибка приложения или базы.
